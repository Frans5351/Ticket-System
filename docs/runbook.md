# Runbook

Operational information for keeping Park Manor running, deploying changes, and recovering from problems.

## Deployment

### Standard flow (via GitHub → Netlify)

1. Local changes → commit → push to `master` on `Frans5351/Ticket-System`
2. Netlify auto-deploys within ~1 minute
3. `deploy.txt` in the deployed site shows the build UTC timestamp — sanity check by hitting `https://park-manor-bc.netlify.app/deploy.txt` in a browser

### Manual deploy (drag-and-drop)

If GitHub → Netlify integration is broken, or you want to deploy an unofficial build:

1. Get the current build zips (`park_manor_deploy.zip` contains the full project including Netlify functions)
2. Netlify Dashboard → Deploys → drag the zip onto the deploy zone
3. Netlify takes ~30 seconds to publish

### Build variants

Three zip packages, generated by the build script:

| Package | Contains | Use for |
|---|---|---|
| `park_manor_deploy.zip` | `public/`, `functions/`, `netlify.toml` | Full Netlify deploy (has passkey + email) |
| `park_manor_public_only.zip` | Just `public/` | Quick static-only redeploy (no function changes) |
| `Park_Manor_local.zip` | Local dev server + config | Local dev with `python3 server.py` |

The standalone `index.html` at the root of outputs is a **single-file drop-in** — works without any of the Netlify functions. Passkey enrolment and emailing edit links won't work, but everything else does.

## Environment variables

Set in Netlify → Site settings → Environment variables. Redeploy after changing (env vars are baked into function context on deploy).

### Required for full functionality

| Variable | Set to | Used by |
|---|---|---|
| `SUPABASE_URL` | `https://spagcmzhlngtqvrydzvi.supabase.co` | All backend functions |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API → `service_role` | All backend functions |
| `PM_JWT_SECRET` | Random 32+ char string | `passkey-password-login` (JWT signing) |

### Required for email-the-link feature

| Variable | Set to | Notes |
|---|---|---|
| `RESEND_API_KEY` | From resend.com → API Keys (starts `re_`) | Missing → function returns 500 |
| `RESEND_FROM` | e.g. `Park Manor <noreply@yourdomain.com>` | Optional, defaults to Resend sandbox sender |
| `PARK_MANOR_NAME` | e.g. `Park Manor Body Corporate` | Optional; controls subject line + branding |

### Resend sandbox sender caveat

If `RESEND_FROM` is left unset (or is `onboarding@resend.dev`), Resend will **only deliver to email addresses you've personally verified** in your Resend account. To send to anyone, verify a domain:

1. Resend → Domains → Add domain
2. Add the DNS records Resend provides (SPF, DKIM) at your DNS provider
3. Wait for verification
4. Change `RESEND_FROM` to use your domain

## Common operations

### Adding a new user

Sign in as admin → Settings → Users → New. Set:
- **Username** (unique login)
- **Full name** (display)
- **Role**: `resident` is the safest default for new residents; `trustee` grants approval powers; `admin` should stay small
- **Password**: any length; users are prompted to change it after login
- **Email / phone**: optional

**Note on plaintext passwords:** the password field is stored in cleartext. Don't use passwords that are shared with other services.

### Toggling the public reporting form

Settings → 🌐 Public reporting → checkbox.

- **On:** shows the URL to share (`?contact-public`) with a Copy button
- **Off:** the link still resolves but shows a "Submissions currently disabled" message; new submissions can't be made
- Doesn't affect existing edit links — residents can still access their `?reportEdit=<token>` submissions

### Linking a public submission to a user

Open the ticket → find the `🔗 Link to existing user` dropdown below the reporter fields → pick a user. Replaces the reporter's free-text name with the user's full name and sets `reporterUserId`.

To unlink (admin only): the green "Linked to X" badge has a small `unlink` button.

### Recovering from a stuck approval flow

If a ticket is stuck in `awaiting_trustee_approval` and votes aren't advancing:

1. Open the ticket
2. Check the approval panel — how many trustees have voted on each item?
3. If votes are spread across multiple items (2 for quote A, 1 for quote B, 1 for proposal C) → the threshold is never met. Trustees need to converge on one item.
4. Admin override: change the status directly from the Status dropdown. Overrides the approval rule.

## Common failure modes

### "Attachments not available yet" warning

**Symptom:** Ticket has linked docs but they show a warning banner instead of appearing.
**Cause:** The invoice record exists in Supabase but the current browser hasn't loaded it (either not fetched yet, or `INVOICES[id].data` is empty).
**Fix:** As admin, click the `↑ Resync` button in the ticket modal header. It pulls missing photos from Supabase AND pushes local-only photos up. Report `✓ downloaded N, uploaded M`.

### Copy button doesn't seem to work on iOS

**Symptom:** User taps "Copy link" — nothing happens.
**Cause:** iOS Safari rejects `navigator.clipboard.writeText` in some contexts. The fallback `execCommand('copy')` also fails on iOS in modern versions.
**Fix:** The copy handler already selects the URL text on screen as a last resort. User can long-press → Copy from the iOS context menu.

### Public form submits but no email arrives

**Symptom:** User ticked "Email me my edit link", saw "✓ Sent to <email>", but the email doesn't arrive.
**Diagnosis path:**
1. Check spam folder
2. Netlify → Functions → `send-edit-link` → Recent invocations → click the failed one → view logs
3. Most common: sandbox sender + unverified recipient. Fix: verify the email in Resend, or verify your domain
4. Second most common: `RESEND_API_KEY` unset or expired. Fix: reset in Netlify env vars, redeploy

### Ticket saves seem to overwrite each other

**Symptom:** Two people edit the same ticket at once; one's changes are lost.
**Cause:** Last-write-wins on Supabase. No optimistic concurrency check.
**Prevention:** The `visibilitychange` listener resyncs data when a tab regains focus, minimising this in normal use. There's no true fix without adding version numbers to records.

### Sara scenario — a user's overrides don't apply

**Symptom:** A user's `permissions[key]` override was set but doesn't take effect.
**Cause historical:** `loadUsers()` replaced individual `USERS` records wholesale, orphaning `_currentUserObj` which held stale data.
**Fix already applied:** after `Object.assign(USERS, remote)`, we re-link `_currentUserObj = USERS[_currentUserObj.id]`.
**If you see this recurring:** check the login flow's `applyUserSession` and confirm `_currentUserObj` re-linking is intact.

## Known issues / tech debt

Ranked roughly by severity:

1. **Passwords are plaintext.** Fix requires a Netlify function for bcrypt hashing + login. Non-trivial refactor.
2. **Photos stored as base64 in `invoices.data`.** Rows can be 5-10MB. Slow queries at scale. Fix requires migrating to Supabase Storage + updating the render pipeline to fetch URLs.
3. **No RLS policies.** Supabase Row-Level Security is off. Access is enforced only by the anon key + app-level checks. If the anon key leaks, everything is readable.
4. **Hardcoded admin path.** The legacy "admin/admin" fallback bypasses the server endpoint (no JWT, no passkey). Kept because losing access is worse than the weak auth. Retire once passkey enrolment is universal.
5. **Concurrent-edit races.** Last-write-wins. Rare in practice but real.
6. **Long conversation state on visibilitychange.** The tab-refocus refetch can cause "docs disappear then reappear" flicker. Mostly fixed but keep an eye on it.
